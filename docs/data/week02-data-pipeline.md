# Week 02 데이터 수집·가공 실행 가이드

## 1. 개요

Week 02 모델 학습 데이터 구축을 위해 사용한
과거 따릉이 대여·반납 이력, 기상 데이터, 달력 데이터의
수집 및 가공 방법을 정리한다.

대여소 데이터는 광진구·성동구 대상 대여소 마스터의
`station_id`를 기준으로 연결한다.

기본 데이터 처리 흐름은 다음과 같다.

```text
원천 데이터
    ↓
raw
    ↓
수집·필터링
    ↓
interim
    ↓
전처리·가공
    ↓
processed
```

원천 데이터는 직접 수정하지 않고 보존한다.

## 2. 과거 대여·반납 이력

### 입력 데이터

서울시 따릉이 과거 대여·반납 이력 데이터를 월별 ZIP 파일로 준비한다.

대상 기간:

- 2025-08 ~ 2026-07

대상 대여소 목록:

```text
data/reference/target_stations.csv
```

### 처리 방법

`target_stations.csv`의 `station_id`를 기준으로
광진구·성동구 대상 데이터만 필터링한다.

대여 데이터:

- `집계_기준 == "출발시간"`
- `시작_대여소_ID`가 대상 `station_id`에 포함되는 행

반납 데이터:

- `집계_기준 == "도착시간"`
- `종료_대여소_ID`가 대상 `station_id`에 포함되는 행

원천 CSV는 `cp949`로 읽고, 인코딩 오류가 발생하는 경우
`utf-8`로 다시 읽는다.

실행 스크립트:

```text
scripts/filter_trip.py
```

## 3. 기상 데이터

기상청 AWS 관측 데이터를 원천 데이터로 사용한다.

Week 02에서는 성동 AWS(지점번호 421)의 시간 단위 관측 데이터를
대상 기간에 맞추어 사용한다.

원천 파일은 다음 경로에 보관한다.

```text
data/raw/weather/
```

원천 데이터의 결측값은 임의로 0으로 변환하지 않으며,
결측 처리 방법은 전처리 규칙에 따라 별도로 결정한다.

## 4. 달력 데이터

공휴일 정보는 한국천문연구원 특일정보 API를 이용하여 수집한다.

실행 스크립트:

```text
scripts/collect_calendar.py
```

가공된 달력 데이터는 다음 정보를 포함한다.

- `date`
- `weekday`
- `is_weekend`
- `is_holiday`

출력 데이터:

```text
data/processed/calendar/calendar_dim.csv
```

## 5. 주의사항

- API Key와 비밀번호는 코드 또는 Git 저장소에 직접 저장하지 않는다.
- 원천 데이터는 덮어쓰지 않는다.
- `station_id`는 문자열로 처리한다.
- 원천 데이터에서 관측되지 않은 구간을 임의로 0으로 처리하지 않는다.
- 대여소 매칭 및 결측 처리 세부 규칙은 `docs/data/preprocessing-rules.md`를 따른다.

## 6. 데이터 수집·적재 흐름

백엔드는 서울시 열린데이터광장 API에서 광진구·성동구 따릉이
대여소 기본정보와 실시간 자전거 현황을 수집하여 MySQL에 저장한다.

### 실행 방법

MySQL과 필요한 환경변수를 설정한 후 `backend` 디렉터리에서
Spring Boot 백엔드를 실행한다.

Windows:

```bash
gradlew.bat bootRun
```

Linux/macOS:

```bash
./gradlew bootRun
```

백엔드가 실행되면 대여소 기본정보 초기화 및 실시간 스냅샷 수집이
설정된 스케줄에 따라 자동으로 수행된다.

백엔드 실행에 필요한 환경변수 및 상세 설정은 `backend/README.md`를 참고한다.

### 대여소 기본정보

```text
서울시 대여소 정보 API
        ↓
광진구·성동구 대여소 필터링
        ↓
station 테이블 저장
```

`station` 테이블이 비어 있는 경우 백엔드 실행 시
대상 대여소 기본정보 초기화를 시도한다.

이후 설정된 스케줄에 따라 대여소 기본정보를 주기적으로 갱신한다.

### 실시간 대여소 현황

```text
서울시 실시간 따릉이 API (bikeList)
        ↓
API 전체 페이지 조회
        ↓
광진구·성동구 대상 station_id 필터링
        ↓
5분 단위 스냅샷 생성
        ↓
station_snapshot 테이블 저장
```

실시간 현황 수집은 5분 주기로 실행된다.

각 수집 시점의 대여소별 이용 가능 자전거 수와 거치대 정보를
`station_snapshot` 테이블에 저장한다.

API 페이지 수집 중 오류가 발생한 경우 불완전한 수집 결과를
저장하지 않도록 전체 페이지 수집 완료 후 DB에 저장한다.

대여소 기본정보가 없는 경우 먼저 대여소 초기화를 시도하며,
초기화에 실패하면 해당 수집 회차를 종료하고 다음 5분 주기에
다시 초기화를 시도한다.
